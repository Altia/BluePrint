    Introduction

    This book is the primary reference for the Altia BluePrint language, ABP. It describes each construct of the language, what it means, and the rules a document must follow to be accepted.

    ABP is a declarative language for describing a human–machine interface (HMI). A BluePrint document is a tree of UI components: the properties on each, the events each one responds to, and the actions those events run. Property values are expressions, and they are reactive: when a value an expression reads changes, the expression is evaluated again and the screen follows.

    The surface syntax is YAML with three deliberate restrictions, and expressions are written in a subset of JavaScript. Drawing, layout, animation and custom GPU materials are part of the language; I/O and heavy computation are left to the host application, which reaches the design through Data objects and external functions.

    Scope of this reference

    This reference covers the language as implemented by the Altia BluePrint toolchain distributed with the Altia BluePrint extension, version 0.9. It describes:

    • the lexical and structural rules of a document (chapters 1–4);
    • the expression language, name resolution and evaluation model (chapters 5–7);
    • events and actions (chapters 8–9);
    • every built-in type and its properties (chapters 10–15);
    • how a host application integrates with a design, and how designs are checked and run (chapters 16–17).

    It is not a tutorial. Readers new to BluePrint should start with the worked examples throughout chapters 10–15 and the recipes in Appendix E.

    Conventions

    The words must, must not, should and may are used in their usual normative sense. A document that breaks a must rule is not a valid BluePrint document. Most such rules are enforced by blueprint --check and reported with a diagnostic (Appendix C). A rule the checker does not yet enforce is marked Not diagnosed: a design that breaks it checks clean but may not behave as intended. Where the language accepts a construct silently by design, the text says so explicitly.

    intro.rulesRules are labeled with identifiers such as lex.indent.spaces. Each identifier is a stable link target; select one to copy a link to that rule.

    Code examples are ABP unless labeled otherwise. Grammar productions use the notation described in chapter 1.

    Note

    Notes give background or rationale. They are informative, not normative.

    Warning

    Warnings describe constructs that are accepted but do something other than what an author would likely expect.

    Reserved

    Reserved callouts describe names that the language accepts but that have no effect in this version. They are listed so that the set of names is closed. Documents should not use them; their behavior may be defined in a future version.

    Examples

    Examples are complete documents or fragments of one. A fragment may read names declared elsewhere in a design (a Data object such as App or Vehicle, a Font, a theme object) and assumes those declarations exist; an example that shows two forms of the same thing side by side is two alternatives, not one document. Comments in examples explain what a line does. Examples that show an error or a pitfall are marked with a warning bar and a comment beginning # WRONG.

    x: parent.x + 10      # WRONG -- child coordinates are already parent-relative

    Lexical structure

    An ABP document is a UTF-8 text file, conventionally with the extension .abp. Its syntax is a restricted form of YAML: every non-blank line is a mapping entry of the form key: value, and hierarchy is expressed by indentation.

    Relationship to YAML

    lex.yaml.restrictABP is YAML with three constructs removed. A document must not use:

    • block sequences (- item): child components are nested by indentation, never listed;
    • anchors and aliases (&name, *name): reuse is expressed with type definitions (§4.2);
    • tags (!type): the type of an object is given by its key.

    lex.yaml.valuesUnlike YAML, a value is never interpreted as a YAML scalar. Every value is an expression. In particular an unquoted word is a name reference, not a string.

    Lines and indentation

    lex.indent.spacesIndentation is made of spaces. Tab characters must not be used for indentation.

    lex.indent.nestingA line indented further than the entry above it is a child of that entry. A line at the same indentation is a sibling. The conventional width is two spaces per level. Within one body every sibling must use the same indentation; a line indented by a different amount is attached to a different parent.

    lex.blankBlank lines and lines that hold only a comment are ignored.

    Comments

    lex.comment.hashAt the document level a comment starts with # outside a string literal and runs to the end of the line. It may stand on its own line or follow an entry.

    lex.comment.exprInside an expression body — including every line of a | block scalar — the text is JavaScript and comments are // line comments. A # inside an expression body, outside a string literal, is a syntax error: App.s = "a # b" is fine.

    # a document comment
Data: App
  count: 0

Text: label            # a trailing comment
  text: "count: " + App.count
  @press:
    code: |
      // a JavaScript comment: this line is inside the block
      App.count = App.count + 1

    lex.key.scopeA :: in key position names a type exported by an aliased import: Ui::Card: cardOne. In value position :: always names an enumeration value (§5.5).

    Values

    lex.value.onelineA value written after key: ends at the end of that line. It cannot continue onto the next line; this applies to every value, including array literals.

    points: [[0, 0], [10, 0],          # WRONG -- the value stops
         [10, 10], [0, 10]]        #          at the end of the line

    lex.value.blockA value of | starts a block scalar. Every following line indented further than the key belongs to the block, and the lines are read together as one expression body. A block is how a long value, multi-statement code, or GLSL source is written.

    points: [[0, 0], [10, 0], [10, 10], [0, 10]]     # one line

points: |                                        # or a block
  [[0, 0], [10, 0],
  [10, 10], [0, 10]]

    lex.value.stringsString values must be quoted, with double or single quotes. text: "Hello" is a string; text: Hello reads the object or property named Hello. Numbers must not be quoted: width: "100" is accepted silently as a string, not a number. Not diagnosed

    Identifiers

    SyntaxIdentifier : [A-Za-z_] [A-Za-z0-9_]* // with at least one letter

    lex.ident.cIdentifiers follow C rules: a letter or underscore, followed by letters, digits and underscores. A declaration name must also contain at least one letter. 1Foo, Foo Bar, Foo-Bar, _ and _9 are not valid names.

    lex.ident.digitA declaration name must not start with a digit. This includes the element names of an array written by elements, so 1: 0 is invalid.

    lex.ident.caseThe casing of an instance name is unconstrained. The first letter of a type name must be uppercase. Underscores and digits before that letter are allowed, as long as the name does not start with a digit: _Button and _9Gauge are type names, while _button and _ are not.

    Top-level structure

    SyntaxDocument : Import* TopLevelItem* TopLevelItem : Declaration | TypeDefinition | EventHandler

    doc.project.singleA single .abp file with no project file is also a complete design; it is its own entry document.

    Imports and modules

    SyntaxImport : "import:" " " ImportSpec EOL ImportSpec : StringLiteral ( " -> " Identifier )?

    A document loaded through import: is a module.

    import: "imports/widgets.abp" -> Ui     # aliased
import: "imports/theme.abp"             # unaliased

    doc.import.aliasAn aliased import exposes the module's types under the alias, as qualified names: Ui::Card, Ui::CardLabel.

    doc.import.mergeAn unaliased import merges the module's type names into the importing document's namespace: Heading: title.

    doc.import.onceA module imported through several paths (a diamond) loads exactly once.

    doc.import.deriveImported types may be used as bases: Ui::CardLabel: $Badge defines a local type derived from an imported one.

    doc.import.transitiveImports are not transitive. A document sees the types of the modules it imports itself, not those of the modules they import. If main.abp uses a type from theme.abp that only buttons.abp imports, main.abp must import theme.abp as well.

    doc.import.parseA module with a syntax error keeps its last good types. The error is reported at its location (doc.parse) and on the line that imports the module (import.module-parse). Until the module parses again, importers see the types from its last good parse, or none if it never parsed.

    doc.import.liveEditing a type definition updates every instance of it. Children that an instance declares itself are kept.

    import: "imports/widgets.abp" -> Ui
import: "imports/theme.abp"

Display: main
  width: 1280
  height: 480

Heading: title            # unqualified: from the unaliased theme.abp
  text: "Import Showcase"

Ui::Card: cardOne         # qualified: from the aliased widgets.abp
  x: 100
  y: 60
  Ui::CardLabel: label    # authored child beside the type's own content
    text: "Alpha"

    A module provides types only

    doc.module.instancesInstances declared at the top level of a module — a Data, Motion, Font, Timer, Display, or named Component — exist only when that module is previewed on its own. A design that imports the module never creates them, and each such declaration is flagged in the module (import.module-instance).

    A type in the module that refers to one of those instances by name therefore finds nothing where the type is used, and the instance in the importing design is flagged expr.stamped-unresolved. There are two correct ways to write it. The first is preferred, because it does not depend on every importer declaring the same name.

    Make the instance part of the type:

    # imports/lib.abp
Component: $Anim
  pos: 0
  Motion: slide              # a child, created with every instance
    Step:
      Tween:
        out: target.pos
        to: 100
        duration: 300
  @init:
    start: slide

# main.abp
import: "imports/lib.abp"
Anim: a1

    Or have the importing design declare the name the type expects:

    # imports/lib.abp
Component: $Anim
  pos: 0
  @init:
    start: slide             # resolved where the type is used

# main.abp
import: "imports/lib.abp"

Motion: slide                # the name the type expects
  Step:
    Tween:
      out: target.pos
      to: 100
      duration: 300

Anim: a1

    Declarations

    Instance declarations

    SyntaxDeclaration : TypeKey ":" ( " " Identifier )? EOL Body? Body : ( PropertyEntry )* ( EventHandler | Declaration | AnimationBinding )* // one level deeper

    decl.instance.formType: name creates one object of Type named name. Its body, indented one level, holds the object's properties, event handlers and children.

    decl.instance.orderWithin a body, properties must precede child declarations. Not diagnosed

    decl.instance.anonThe name may be omitted. An anonymous instance cannot be referenced by name; it can be reached only through this and parent.

    decl.instance.zorderDeclaration order is draw order: a later sibling draws on top of an earlier one. It is also the order of items in a layout (§12.9).

    Image: myImage              # instance: Image type, named myImage
  img: "res/logo.png"       # property assignment
Component: $MyButton        # type definition: new type MyButton
  label: "click me"         # default property value
MyButton: okButton          # instance of the user-defined type
  label: "OK"               # override the default
Ui::Card: cardOne           # instance of Card from the import aliased Ui

    Type definitions

    SyntaxTypeDefinition : TypeKey ": $" TypeName EOL Body?

    decl.typedef.formBase: $Name defines a new type Name derived from Base. The body has the same form as an instance body. Once defined, Name: instanceName creates instances of it.

    decl.typedef.apiProperties declared on the definition are the type's public interface; their values are defaults that an instance may override. Children of the definition are its internal structure.

    decl.typedef.rootlevelA type definition must be at the top level of a document; it must not be nested inside another component.

    decl.typedef.nameThe first letter of the type name must be uppercase (leading underscores are allowed), and the name must not reuse a built-in type name: Component: $Text is rejected.

    decl.typedef.baseAny component type may be a base, including a user-defined type and an imported type.

    decl.typedef.dollarThe $ prefix is reserved for type-definition values. width: $foo is invalid.

    Component: $LabeledIcon
  iconName: ""
  labelText: ""
  Image: icon
    img: iconName
    x: 0
    y: 20
  Text: label
    text: labelText
    x: 0
    y: 0

LabeledIcon: warning
  iconName: "res/warn.png"
  labelText: "Warning"
  x: 40
  y: 60

    Type opacity

    decl.opacity.inThe children of a user-defined type are its private structure and must not be addressed from outside an instance. In the example above, use warning.iconName and warning.labelText, never warning.icon. To expose an internal value, declare a property on the type and have the internal child read it. Not diagnosed

    decl.opacity.outOpacity runs both ways: a definition cannot reach whoever instantiates it. Inside a definition, parent means the definition's own structure, so a chain such as parent.parent.value written to reach the instance's owner resolves to nothing. Declare a property on the type and let the owner bind it at the instance declaration (§6.3).

    Properties

    SyntaxPropertyEntry : PropertyKey ":" ( " " ( Expression | BlockScalar ) )? EOL ElementList?

    decl.prop.assignname: expression binds a property of the enclosing object to an expression. The binding is reactive (§7.1).

    decl.prop.userAssigning a name the object's type does not define declares a user property on that object. A user property is an ordinary reactive value, readable and writable like a built-in one. This is how a Data object holds its fields and how a user type declares its parameters.

    Component: gauge
  sweepAngle: 240          # user property -- nothing built in is called this
  rotate: sweepAngle * 0.5
    Warning

    decl.prop.misspellProperty names are not validated against the type. A misspelled built-in property such as widht: 10, or color: "#fff" (the color properties are fg and bg), is accepted silently as a user property and has no effect. By contrast, unknown type, event and action names are rejected.

    decl.prop.declaredAn optional built-in property that an object leaves unset (x, y, width, …) is not declared on that object. A chain that reaches it from elsewhere (panel.x) is unresolved, and a Motion cannot drive it. Write the property, at its default, on any object whose property is read by chain or animated.

    Arrays written by elements

    SyntaxElementList : ( INDENT Identifier ":" ( " " Expression )? EOL ElementList? )+

    decl.array.formA property whose value is a nested block is an array, one element per line. This is the only meaning a nested block under a property has; it never declares an object.

    borders: [0, 1, 2, 3]       # flat form
borders:                    # element form -- the same four elements
  l: 0
  b: 1
  r: 2
  t: 3

    decl.array.indexDeclaration order is index order, top down. Both forms address the same storage: borders[0] and borders.l are the same element.

    decl.array.namesElement names are chosen by the author. They are labels and access paths, not schema fields, and nothing checks them against the property. The positional meaning is fixed by the property; for borders it is left, bottom, right, top regardless of the names used.

    decl.array.exprElement values are ordinary reactive expressions. An element with children of its own is a nested array, to any depth.

    Name uniqueness and shadowing

    decl.names.uniqueTwo siblings must not share a name (decl.duplicate-name), and a child must not share its parent's name (decl.parent-name). This applies to array elements too: two elements named l are an error, not an overwrite.

    decl.names.shadowA child must not share a name with a property declared in the same scope; that is an error (decl.duplicate-name). An instance or child should not share a name with a property of its type or of its parent — one the type declares or inherits, or a built-in property the type writes: a component answers its own name before its properties, so the name hides the property, or is itself hidden by it. That is reported as a warning (decl.shadows-property).

    Component: $Icon
  glyph: "?"
  Text: t
    text: parent.glyph      # finds the child below, not the property

Icon: glyph                 # WRONG -- instance named like its type's property

    Event and action names (tick, stop, next, key, …) are not properties and are safe as child names.

    Expressions

    The right-hand side of every property assignment, event condition and action is an expression in ABP's subset of JavaScript. It follows current ECMAScript rather than one edition, and includes features such as ?? and the at, includes, padStart and trimStart methods. This chapter defines the subset.

    expr.stmt.setAny expression body may contain let and const declarations and the statements if/else, for, while, do, switch, break and return. Statements are separated by newlines or semicolons.

    Calls

    expr.call.kindsExactly three kinds of callee exist. A call that is none of them — a user function, or an unknown built-in or action name — is refused when the design loads (expr.generate, “Unknown or unsupported function call”).

    expr.call.builtinBuilt-ins come from a closed table. They write nothing, so they are legal in any expression body. All of them except Math.random are pure: the same arguments always give the same result.

    Action calls

    expr.call.actionAn action call applies a component verb to a receiver: myTimer.start(), group.nested.pause(). Action calls act, so they are legal only in a code: action. The verbs are those of chapter 9.

    expr.call.motionA Motion verb takes the object to animate as its first argument: slide.start(panel). Without one the call does nothing.

    expr.call.arityArgument counts are not checked. Extra arguments are ignored (myTimer.start(5) starts the timer); a missing argument reads undefined.

    External functions

    expr.call.extAn external function is implemented by the host and called through the reserved ext namespace, in exactly the form ext.name(…). It is never a method on an object and never nested (ext.a.b() is refused). External calls are legal only in a code: action.

    expr.call.extruntimeExternal names are resolved at run time, so an unknown name is never refused at load. A call that no host answers reads undefined. See §16.2.

    Enumeration values

    SyntaxEnumValue : EnumName "::" ValueName // one token, no spaces

    Resolving names

    scope.res.walkAn unprefixed identifier is resolved through scope: first the owning component's own properties and children, then each ancestor's properties and children, nearest first. This is how a child reads a property its parent declares.

    scope.res.chainOnly the first name of a chain walks scope. A name after a . is a member of the object before it and is looked up on that object alone: this.x, parent.x and card.label.x never fall back to an ancestor's x.

    scope.res.unsetA built-in property that an object leaves unset is not declared on it, so a chain that reads it (warningLamp.alpha with no alpha: on warningLamp) is reported unresolved, and reads the default at run time, while a write or a Motion through it changes nothing. Write the property, at its default, on any object whose property is read, written or animated through a chain (decl.prop.declared).

    scope.res.unresolvedIf a chain names nothing it is unresolved and is diagnosed expr.resolve. At run time, reading it yields nothing and writing it changes nothing, with one exception: a chain ending in a built-in property the object leaves unset reads that property's default (alpha reads 255, x reads 0).

    scope.res.bynameObjects are addressed by their declared names: Vehicle.speed. Domain prefixes such as data. or strings. must not be used. They are accepted silently, and data.speed resolves against the first top-level object of that kind, which is rarely the one intended. Not diagnosed

    The type boundary

    scope.type.parentInside a type definition, parent stops at the type boundary: it means the definition's own structure, not the instantiator.

    scope.type.deferredSome chains in a type body cannot be judged where they are written, because they depend on the instance: parent.x when the definition does not declare x, and a member of a property the type declares (model.value with model: 0). These are not reported in the body. Each instance resolves its own copy, and a chain the instance's site cannot satisfy is reported on the instance declaration as expr.stamped-unresolved; the message quotes the chain and names the segment where resolution stopped (parent.zz.qq names zz).

    scope.type.onceA chain binds once. A segment that names nothing is dead for the life of that binding; it does not start working later. Rewriting a chain as a subscript (parent["x"]) does not help and breaks the binding.

    The correct pattern gives the type its own property and lets the owner bind it, one hop, at the instance declaration:

    Component: $Slider
  value: 0                         # the type's own, drawn by its children
  Shape: fill
    points: [[0, 9], [200 * parent.value, 15]]

Component: $Row
  value: 0
  Slider: sl
    value: parent.value            # the owner binds it -- always valid

    Scope inside handlers

    scope.handler.transparentEvent handlers and actions are scope-transparent. Inside a condition or an action body, this is the component that owns the handler and parent is that component's parent. The event's own payload is reached through src.

    Evaluation model

    Reactive bindings

    eval.reactive.defaultProperty bindings are reactive. When a value changes, every property expression that reads it is evaluated again, and anything that reads those properties follows in turn.

    Data: Vehicle
  speed: 0

Text: speedReadout
  text: Vehicle.speed + " km/h"     # re-evaluates whenever Vehicle.speed changes

    eval.handlers.ondemandEvent handlers are the exception. A handler's condition is evaluated when its trigger fires, and an action body when it runs; neither is re-evaluated when something it reads changes. A condition therefore sees state as of the moment of dispatch. The one reactive trigger is @if (§8.2).

    Writes belong to code actions

    eval.writes.ruleAn expression that writes state is a procedure, not a value. It is legal only as the body of a code: action. In any other position — a property value, an event condition, a log: body — it is refused (expr.side-effects).

    eval.writes.whatWrites are: =, the compound assignments and ++/-- applied to a property or array element; action calls; and external ext.* calls. Reads are unrestricted, and assigning a let local is not a write.

    Data: state
  count: 0

Text: readout
  text: "count: " + state.count      # value: a pure read
  @press:
    code: state.count += 1           # procedure: the write is allowed here
    text: state.count += 1               # WRONG -- write in a value slot

    Run mode

    eval.run.handlersEvent handlers dispatch only while the design is running. Rendering and property propagation remain live when it is stopped, so an editor shows a live design whose handlers are silent.

    eval.run.init@init is delivered to the whole tree when the design starts, and again on every restart. It is not a construction-time hook.

    Events

    Handler syntax

    SyntaxEventHandler : "@" EventName ":" ( " " Condition )? EOL Action* // actions one level deeper; an empty handler is accepted Condition : Expression

    ev.syntax.condAn event handler is an @-prefixed key whose optional value is a condition. The handler runs only if the condition is truthy when the trigger fires. Its children are actions.

    ev.syntax.caseEvent names are camelCase and must be spelled exactly as listed: @press, @doubleTap. @Press and on-press are not event names.

    ev.syntax.whereA handler may be placed on any component body and at the top level. It must not be placed under a property, or nested inside another handler or action.

    Component: powerButton

    log: "pressed"
  @release: App.armed              # condition-gated handler

    ev.triggers.noneThere is no wildcard trigger, and there are no swipe or fling triggers. A swipe is a condition over the release payload (@release: src.xVelocity < -200); a fling is a Motion started from that handler with the release velocity (§13.8).

    The @if trigger

    ev.if.reactiveThe condition of @if is re-evaluated whenever a value it reads changes, and the handler runs each time that re-evaluation is truthy. It is the way to run an action when a value changes, as opposed to merely displaying the value.

    ev.if.cond@if must be given a condition; without one it never fires. Not diagnosed

    ev.if.initial@if does not fire for the state at startup, only when a value it reads changes. To act on the initial state as well, handle @init too.

    Data: Vehicle
  speed: 0

Text: warning
  text: "SLOW DOWN"
  visible: false
  @if: Vehicle.speed > 120
    code: visible = true

    A condition that always reads true, such as @if: nav.tab >= 0, runs on every change of the values it reads.

    The @tick trigger

    ev.tick.frame@tick fires once per rendered frame. It ignores any Timer period. To run something once per period, handle the timer's @complete.

    Pointer triggers

    ev.pointer.semanticsThe pointer triggers behave as follows:

    TriggerFires when
    pressA button goes down over the object
    releaseEvery button-up of the button that armed the gesture, with the final payload
    clickPress then release without a drag, of any duration
    tapPress then release within 200 ms
    doubleTapA tap whose release comes within 1000 ms of the previous tap's release. It replaces that second tap: no @tap fires for it
    holdA press lasts 500 ms without dragging
    enter leaveThe pointer enters or leaves the object
    hover hoverX hoverYThe pointer moves inside the object while no press on that object is being tracked; the axis variants only when that axis moved in the delivery
    drag dragX dragYThe pointer moves while pressed, past a 2 px dead zone; the axis variants only when that axis moved

    ev.pointer.viewablePointer triggers fire only on viewable objects. On a logical object such as a Timer or Data they never fire.

    ev.pointer.nosuppressclick, tap and doubleTap do not suppress release; both fire. A doubleTap does replace the tap it completes.

    ev.pointer.timingGesture timing is fixed and cannot be changed from ABP: tap 200 ms, double-tap 1000 ms, hold 500 ms, drag dead zone 2 px.

    ev.pointer.buttonButton identity is part of the payload, not the trigger. Every button arms the gesture machine; a condition selects a button with src.button == Button::Right. The values are Button::None, Button::Left, Button::Middle and Button::Right.

    ev.pointer.disabledA component whose enabled property is false is transparent to pointer input and stops receiving @tick.

    The src payload

    ev.payload.propsDuring a pointer dispatch, src exposes:

    PropertyMeaning
    x yCurrent pointer position
    startX startYPosition at press
    lastX lastYPosition at the previous delivery
    deltaX deltaYMovement since the previous delivery
    xVelocity yVelocityVelocity in pixels per second
    startTime currentTimeTimestamps of the press and of this delivery
    buttonA Button value

    ev.payload.lifetimeThe payload is valid only during a pointer dispatch: src is cleared when the handler returns. In other handlers src is a different source — the Motion in a run's @start/@complete, the handler's own event object in @if, which has no pointer fields, and nothing in @tick or a timer's events.

    ev.payload.nonreactivePayload properties are not reactive. An expression that reads them is not re-evaluated as the pointer moves.

    ev.payload.velocityOn @release the velocity is the drag's final sample. A flick keeps its last real sample; a pause before letting go reads zero.

    Data: Nav
  page: 0

Shape: ball
  kind: ShapeType::Ellipse
  points: [[0, 0], [40, 40]]
  x: 0                             # declared, so the handler can move it
  y: 0
  @drag:
    code: |
      x = x + src.deltaX
      y = y + src.deltaY
  @release: src.xVelocity < -200   # a leftward swipe
    code: Nav.page = Nav.page + 1

    Action syntax

    Sizing a picture

    type.image.naturalA plain raster draws at its natural size. Setting width/height on an Image sets the component's box — its hit area, its layout basis, and the coordinate space of its children — and does not scale the pixels.

    type.image.resizeThree things resize the picture:

    • A layout slot. An Image fills the box a layout computes for it (§12.7).

    type.image.grayscaleA PNG with no color channels loads as an alpha raster and is drawn in the component's fg. In a gray-only file the gray value is the coverage, white being fully covered; in a gray-plus-alpha file the alpha channel is the coverage. Color PNGs draw as they are.

    type.image.grayfgA mask image without its own fg draws in the nearest ancestor's fg, or black if none is set; bg plays no part. Bind fg to a theme value and one anti-aliased asset re-tints for every theme.

    Data: Theme

    Anti-aliasing

    type.shape.svgsvg: true anti-aliases every edge; svg: false draws the same figure with hard edges. Hard edges suit a large flat Rect such as a backdrop, whose axis-aligned edges gain nothing from anti-aliasing.

    type.shape.svgmaterialA Shape drawn through a material always draws hard-edged, whatever svg says; writing svg: true on one logs a warning. A corners warp applies either way.

    Rounded corners

    type.shape.filletEach rounded vertex becomes a circular arc tangent to both of its edges. Two arcs sharing an edge never use more than that edge, so an oversized radius produces a pill, never an inverted corner. A vertex's own [x, y, r] overrides radius; r of 0 keeps that vertex sharp.

    type.shape.rectradiusA Rect takes radius only. Its two points are opposite corners, so an [x, y, r] there rounds nothing and is reported as a warning (shape.rect-vertex-radius). For per-corner rounding, use a four-point Polygon.

    type.shape.polylineendsThe end points of a Polyline never round.

    type.shape.outlineA sharp Rect's outline is inset when the Rect is unrotated or rotated by a multiple of 90°; at any other angle it is centered on the edge. A rounded Rect's outline is centered on the rounded edge, as a Polygon's is. A wide outline therefore sits half its width further out once the Rect is rounded.

    Buffer, blur and mask

    view.buffer.sizebuffer caches the subtree as an image. It looks the same as drawing directly, and content changes update the cache automatically. A buffered component, like a blurred one, needs its own width and height; without them it draws nothing.

    view.mask.defmask names another component whose alpha coverage stencils this one: only the parts the source covers are drawn. Any viewable may be a source.     view.mask.modeMaskMode::Normal shows content where the source is opaque; ::Invert where it is transparent; ::None disables the coverage.

    view.mask.hidemaskHideSource: true stops the source drawing on its own, making it a coverage-only stencil. The setting on any component the source masks hides the source for all of them, so set and clear it on the same component.

    view.effects.exclusivebuffer, blur and mask are mutually exclusive on one component. If more than one is present when the component first renders, the priority is mask > blur > buffer. Afterwards, whichever is applied first holds the component, and the others take effect only once it is cleared; clearing falls through to the highest-priority remaining effect.

    view.blur.anchorWhile blur is on, a component rotates and scales about its own origin and ignores anchor. A blurred component that is also rotated or scaled therefore jumps when blur toggles. Avoid combining blur with rotate, xScale or yScale about a non-origin anchor in this version.

    A Motion is a reusable animation: a program of sequential Steps, each holding operations that run concurrently, applied to a target object when a handler starts it.     motion.step.seqSteps run in order. A Step ends when none of its operations still holds it open; the next Step then starts. No operation writes past its own Step, so a Spring that should keep settling while something else happens belongs in the same Step as that thing.

    motion.guardSteps and operations have no names. Their value position is an optional guard, evaluated each time the Step or operation arms: a false Step guard skips the whole Step; a false operation guard skips that operation while its siblings run.     Variables

    mat.var.defEvery uniform in either stage whose name does not contain ALTIA_ is a variable that a Material may set. Its type is its GLSL type. Its default is the value in a DEFAULT "…" comment on the same line — up to 16 numbers separated by spaces or commas — else zero. A NAME "Label" comment is accepted and ignored.

    uniform vec4  u_tint;    // NAME "Tint" DEFAULT "1.0 1.0 1.0 1.0"
uniform float u_phase;   // DEFAULT "0.5"
uniform bool  u_flip;    // an int variable: 0 or 1
uniform float u_taps[4]; // one variable named u_taps
uniform sampler2D u_overlay;

    mat.var.scanVariables are found by scanning declarations:

    • One declaration per line; a uniform split across lines is not seen.
    • layout(…) and precision qualifiers are skipped; interface blocks are not variables.
    • Several declarators on one line each become a variable; an array declarator binds by its base name (u_taps[4] → u_taps).
    • The first stage to declare a name wins, vertex before fragment.
    • Limits: 50-character identifiers (longer is truncated; a MatVar name over 50 characters is refused) and 2048-character lines (longer is cut). Stay within Altia Design's limit of 256 uniforms; the BluePrint runtime does not enforce it.

    Compilation lifecycle

    mat.life.compileA shader compiles when a Material first names it. After that it recompiles only on request. Editing a stage marks the shader changed since the last compile, and the running program keeps drawing the previous GLSL.

    mat.life.recompileIn the editor, a single shader is recompiled from its hover (“Recompile this shader”) or the code action on its Shader: line; every changed or failed shader of a document from the context menu (“Recompile Shaders”) or the Altia BluePrint status menu. Stopping or restarting the design recompiles every bound shader.

    mat.life.failOn a compile failure the previous program stays live if there was one; otherwise the shader's users draw with the engine's built-in program. The compiler log is reported on the offending GLSL line inside the block, or on the Shader: key when the error has no line or is in a default stage.

    mat.life.deleteA material that names a deleted shader draws its users with the built-in program until it is pointed at another shader.

    Limitations

    • An ES 3 context is required for the default stages.
    • Transform (Xform) variables, samplerCube values, mat2, integer and boolean vectors, multi-pass materials and 3D materials are not supported.
    • Programs are not cached across a stop/restart; every bound shader recompiles.
    • Only buffer: true components can be texture sources; blur output cannot.
    • Uniform declarations spanning lines are not scanned.

    Host integration

    ABP is not intended to express I/O, search or heavy computation. Those belong in the host application, which reaches the design in two ways: through Data properties, and through external functions the design calls.

    The Data interface

    host.data.reachThrough the runtime API a host reads, writes and watches Data properties by dotted path (Vehicle.rpm). Nothing other than Data properties is reachable.

    host.data.writeA host write is accepted only while the design is running, and only by a writable property authored as a literal or constant expression. A refused write reports its reason: not running, read-only, or dynamic expression for a bound property such as speed: rpm / 30. An accepted write propagates exactly like a code: write.

    host.data.watchA watch reports changes to the property, whoever wrote them. Over the client API and the language server, changes are collected and sent once per frame, so a property written several times within one frame reports only its last value.

    External functions

    host.ext.registerA host makes a function callable as ext.name(…) by registering it under that name. An application registers functions with HMI::API::registerFunction, or through the altia-blueprint-client library. In Visual Studio Code, the Altia BluePrint extension loads a JavaScript module named externals.js, looked for first beside the entry document and then at the root of the workspace folder; each exported name is callable. The ABP is the same in every case.

    // externals.js -- each exported name is callable as ext.NAME(...)
module.exports = {
    formatSpeed(mps) { return (mps * 3.6).toFixed(1) + " km/h"; },
    greet(name)      { return "Hello, " + name + "!"; },
};

    host.ext.patternExternal calls are legal only in a code: action. A property cannot read an external directly (text: ext.formatSpeed(27.8) is refused with expr.side-effects). The pattern is always: a handler calls the function and writes a Data property; the display reads the property reactively.

    Data: state
  speed: ""
  greeting: ""
  presses: 0

Component: driver
  @init:
    code: |
      state.speed = ext.formatSpeed(27.8)
      state.greeting = ext.greet("Altia")

Text: speedOut
  text: state.speed

Shape: regreetBtn
  kind: ShapeType::Rect
  points: [[0, 0], [220, 44]]
  @press:
    code: |
      state.presses += 1
      state.greeting = ext.greet('press ' + state.presses)

    host.ext.unknownWhich host answers a name is decided at call time, so a misspelled name is not an error anywhere; the call reads undefined. ABP names and host registrations must match exactly.

    host.ext.syncCalls are synchronous and hold the frame while the host answers. Every call goes out to the host by name. A host outside the engine (the VS Code extension, or an application using the client library) has one second to answer; a call past that deadline reads undefined. An asynchronous implementation is still waited on.

    host.ext.slowFor slow work, the call should start the work and return at once. The host then writes the result to a literal Data field that an @if handler watches; or, if the host only answers calls, a repeating Timer polls a second function for the result.

    Pressable button as a reusable type

    Component: $PrimaryButton
  labelText: ""
  tone: "#333344"
  @press:
    code: tone = "#5566AA"
  @release:
    code: tone = "#333344"
  Shape: face
    kind: ShapeType::Rect
    points: [[0, 0], [160, 48]]
    bg: tone
    fg: tone
  Text: lbl
    text: labelText
    justify: Justify::Center
    width: 160
    x: 0
    y: 8

PrimaryButton: okButton
  labelText: "OK"
  x: 100
  y: 60

    A plain Component draws nothing, so the press feedback needs something that draws: the face Shape fills with the type's tone. justify centers within the Text's own width.

    Gauge needle driven by data

    Data: Vehicle
  rpm: 0            # 0..8000

Image: face
  img: "res/tach_face.png"
  x: 170
  y: 90
  Image: needle
    img: "res/needle.png"    # same size as the face, pointing straight up
    x: 0
    y: 0
    width: 300               # the art's size: an Image needs it for anchor
    height: 300
    anchor: [0.5, 0.5]
    rotate: 135 - Vehicle.rpm / 8000 * 270

    The needle art is the same size as the face and points straight up, so placing it at x: 0, y: 0 lines the two pictures up and the center anchor is the dial's pivot. An Image honors anchor only when its width and height are set (type.image.anchor). Positive rotation is counterclockwise, so the angle starts at 135° (pointing down and to the left at 0 rpm) and decreases, sweeping the needle clockwise through 270° to −135° at 8000 rpm.

    State-dependent imagery

    Data: App
  level: 0        # 0..4

Image: gauge
  img: "res/level_" + App.level + ".png"

    The path re-evaluates whenever App.level changes; an image must exist for every reachable value.

    Gauge fill swept by a mask

    Data: Gauge
  pct: 0                       # 0..100

# A coverage-only rectangle that slides across the bar.
# At pct 0 it sits entirely left of the bar; at 100 it covers it exactly.
Shape: fillStencil
  kind: ShapeType::Rect
  points: [[0, 0], [200, 24]]
  bg: "#ffffff"
  x: -161 + 200 * (Gauge.pct / 100)     # -161, not -160: no 1-px sliver at 0%
  y: 80

Component: fuelBar
  x: 40
  y: 80
  mask: fillStencil
  maskHideSource: true         # the stencil shapes the mask but never draws
  Image: fillArt
    img: "res/bar_fill.png"    # the full fill artwork, masked
    x: 0
    y: 0
    width: 200
    height: 24

    For an arc gauge, rotate the stencil instead: author a square wedge image whose pivot is its center, place that center on the dial pivot, give the Image its width and height so it turns about that center (type.image.anchor), and bind rotate. Keep the stencil and the masked component under the same parent so the overlap arithmetic stays readable; the stencil is positioned in its own parent's frame.

    Animated show/hide driven by state

    Data: nav
  tab: 0

Motion: $Reveal
  Step:
    Tween:
      out: target.alpha
      to: target.shown ? 255 : 0
      duration: 350
      ease: Ease::InOutSine
    Tween:
      out: target.y
      to: target.shown ? 80 : 40
      duration: 350
      ease: Ease::OutCubic

Reveal: reveal

Component: $Page
  shown: false
  alpha: 0
  y: 40
  visible: alpha > 0
  enabled: alpha > 0
  @init:
    start: reveal           # @if does not fire for the initial state
  @if: nav.tab >= 0
    start: reveal
  Shape: face
    kind: ShapeType::Rect
    points: [[0, 0], [400, 200]]
    radius: 12
    bg: "#1E3A5F"

Page: home
  shown: nav.tab == 0
  Text: heading
    text: "Home"
    x: 24
    y: 150

Page: settings
  shown: nav.tab == 1
  Text: heading
    text: "Settings"
    x: 24
    y: 150

Shape: switcher
  kind: ShapeType::Rect
  points: [[0, 0], [120, 40]]
  x: 440
  y: 80
  bg: "#5FB0FF"
  @click:
    code: nav.tab = nav.tab == 0 ? 1 : 0

    Each page watches state with @if and starts the Motion on itself, and @init covers the starting state, which @if does not fire for (ev.if.initial). Because to is read when the Step starts and from defaults to the current value, switching pages mid-transition continues smoothly from wherever each property is now. Visibility and input follow the animated alpha, so the hidden page cannot be clicked.

    Wipe by animating the clip window

    Data: reveal
  w: 0

Motion: $Wipe
  Step:
    Tween:
      out: reveal.w
      to: 200
      duration: 400
      ease: Ease::OutCubic

Wipe: wipe

Component: card
  width: 200
  height: 100
  clip: true
  clipRect: [0, 0, reveal.w, 100]
  @init:
    start: wipe
  Image: art
    img: "res/card.png"
    width: 200
    height: 100

    A Motion cannot drive one array element, so it tweens a scalar that the clipRect element reads. Wipe from the right with clipRect: [200 - reveal.w, 0, reveal.w, 100]. To wipe vertically, animate the fourth value instead, from its own Data field tweened to the card's height, 100; because +Y is up, the card is revealed from the bottom up.

    Glossary

    ABP
    Altia BluePrint, the language this reference describes.
    Action
    A step inside an event handler, written as a bare key (chapter 9).
    Design
    An entry document together with every module it imports.
    Entry document
    The document named by abp.project.yaml's entry, or a lone .abp file: the top of the design's tree.
    External function
    A host-implemented function called from a code: action as ext.name(…).
    Instance
    One object of a type, created by a declaration.
    Item
    A component positioned by an enclosing layout.
    Logical type
    A type without graphic content: Timer, Data, Font, Layout, Motion, Display, Shader, Material, Texture.
    Main axis / cross axis
    The direction set by flexDirection, and the one perpendicular to it.
    Module
    A document loaded through import:. A module provides types only.
    Reactive
    Re-evaluated automatically when a value it reads changes; the default for property bindings.
    Run
    One application of a Motion to one target.
    Run mode
    The state in which event handlers dispatch.
    User property
    A property an author declares by assigning a name the type does not define.
    User type
    A type defined with Base: $Name.
    Viewable
    A type that takes part in drawing — Component, Image, Text, Shape, Stamp, Scene and types derived from them — and has the common surface of chapter 11. A plain Component draws nothing itself but is still viewable.
